## Fixes made

### Fix 1 -- Journey Step 3: header name wins over a disagreeing filename guess (commit `a2d3cbf`)

Caught live during the audit: `guessNameFromCV` previously let a filename-derived guess silently override a
**correct** header-derived name whenever the two shared no token -- a mechanism originally built to recover
from a real production bug (PDF extraction intermittently returning garbled header text). Fixture
`strong_pm.pdf` with header "Zendaya Okonkwo-Platt" got stored as "Strong Pm" instead, purely because the
filename happened to also look name-shaped.

Per your decision: the header now wins whenever it independently passes `isPlausibleName`; the filename is
only used when the header is missing or invalid. `isPlausibleName` gained an institutional-word check
(office, delivery, global, solutions, ...) so a genuinely garbled header like "Global Delivery Office" still
correctly fails and falls through to the filename -- the original bug this logic was built for still
recovers. When both are valid but disagree, the filename guess is returned as `conflictingName` and its
tokens are redacted too, even though it isn't used as the identity. Added 3 tests matching your exact
spec (`test/pii-guard.test.ts`): header-wins-and-both-redacted, garbled-header-falls-through, and
`Resume_Final.pdf`-contributes-nothing. Full suite: 93/93 passing after this fix.

### Fix 2 -- Journey Step 8: root cause of run-on email paragraphs (commit `2e58451`)

A live Gemini-generated invite draft had its entire body as one continuous line -- the system prompt never
actually told the model to use blank-line paragraph breaks between the greeting, message, and sign-off. The
earlier session fix (sending a matching `html` part alongside `text`) only helps when the stored text has
`\n\n` to convert into separate `<p>` tags; it can't recover structure that was never generated. Fixed the
prompt to explicitly require blank-line-separated paragraphs, and added `ensureParagraphBreaks` as a
defensive no-op-if-already-structured safety net for whatever the model still returns unstructured. Added 3
tests (`test/email-format.test.ts`). Verified end-to-end on the live send in step 10/11: the delivered
email's html has 4 clean separate `<p>` tags.
